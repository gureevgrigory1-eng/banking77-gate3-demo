# Демо-банк: RAG прототип для Gate 3

[Открыть публичное демо](https://d5dguggs5hklduk1kqbv.g2n58e0c.apigw.yandexcloud.net/)

Учебный ассистент рассказывает о шести вымышленных продуктах, сравнивает их и объясняет оформление. Продуктовая структура вдохновлена Т-Банком, но названия и условия придуманы для задания. Операции с настоящими счетами и передача реальному оператору не выполняются.

## Работа с вопросом

1. TF-IDF по словам и символьным сочетаниям выбирает пять из 30 статей. Для общего вопроса о продуктах в подборку входит каталог.
2. GigaChat-2-Max одновременно выбирает маршрут и формулирует ответ по найденным статьям и последним трём парам сообщений.
3. Сервер проверяет, что указанные моделью ID источников входят в найденную пятёрку. Интерфейс показывает раскрываемые статьи с версией и датой.
4. Личный статус уточняется без выдумывания данных; инцидент направляется в демонстрационный сценарий подготовки обращения. При сбое модели возвращается текст найденной статьи с пометкой резервного режима.

**Ограничение поиска:** эмбеддинги GigaChat для этого аккаунта вернули HTTP 402. Векторный индекс не создан; активен лексический поиск, после которого GigaChat смысловым образом отбирает сведения и строит ответ. Код поддерживает заранее подготовленный векторный индекс и RRF, если доступ к эмбеддингам появится. Наличие этой опции не означает, что она работает в опубликованном демо. Отдельная векторная БД не используется.

## Демо сценарии

- «Какие продукты есть?» — обзор каталога.
- «Чем отличаются карты?» — сравнение дебетовой, кредитной и детской карт.
- «Как оформить дебетовую карту?» → «А какие документы нужны?» — продолжение диалога.
- «Как заблокировать карту?» — общая инструкция.
- «Я не узнаю списание» — безопасный ответ и симуляция обращения сотруднику.

Запросы вне базы получают сообщение о недостатке сведений и уточнение. `/api/ask` принимает `query` и необязательную `history` в формате `[{"role":"user|assistant","text":"..."}]`; старый формат с одним `text` поддерживается. `/api/health` показывает число статей и `semantic_index_ready`.

## Проверка

`evaluation/dev.json` содержит 20 настроечных случаев; `evaluation/control.json` — отдельные 80 контрольных (40 справочных, 10 диалоговых, 10 вне базы, 20 опасных). Скрипт `scripts/evaluate_rag.py` сравнивает генерацию с TF-IDF, который возвращает текст первой статьи без генерации. Результаты: Recall@5 50/50 у обоих подходов; покрытие ожидаемых фактов регулярными проверками 40/50 у RAG и 44/50 у бейзлайна; обнаружение опасных обращений 20/20. p50/p95 общего времени RAG — 1,71/3,41 с; p95 ответов по базе — 3,46 с. Три ответа перешли в резервный режим. Израсходовано 42 355 токенов, из них 36 355 входных и 6 000 выходных; эмбеддингов — 0.

Проверки регулярными выражениями не являются независимой экспертизой точности; 80 примеров синтетические и подобраны автором. Цель 95% по покрытию фактов пока не достигнута. Старые результаты классификатора Banking77 относятся к иной задаче: accuracy 0,905 на английском официальном test split и 0,800 на 30 синтетических русских фразах. Они не измеряют качество RAG.

Локальные тесты: `PYTHONPATH=. python -m unittest discover -s tests -v`. Полный контрольный прогон с работающим GigaChat: `python scripts/evaluate_rag.py`. Для запуска локального интерфейса: `python app.py` (Python 3.12, зависимости из `requirements.txt`). Без ключа GigaChat ответы переходят в резервный режим.

## Размещение и защита

Публичный адрес обслуживает Yandex API Gateway; Cloud Function `banking77-demo` остаётся закрытой. Ключ авторизации хранится в Yandex Lockbox и передаётся функции как `GIGACHAT_AUTH_KEY`. В Git и ZIP его нет. API использует проверку TLS с официальным корневым сертификатом Минцифры `data/russian_trusted_root_ca_pem.crt`; исходник сертификата указан в [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates). Функция ограничивает один запрос 25 секундами, а интерфейс запрещает вводить реквизиты и секретные коды.

У демонстрации нет CRM, очереди сотрудников, доступа к банковским системам и независимой проверки контента. Числовые учебные условия хранятся в `product_catalog.json` и отражены в статьях `knowledge_base.json`.
