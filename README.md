# Gate 3: учебный AI-ассистент банковской поддержки

Прототип для ДЗ № 3: посетитель задаёт вопрос, система выбирает ответ из учебной базы знаний, уточнение или подготовку обращения для сотрудника. Английский классификатор обучен на [Banking77](https://huggingface.co/datasets/PolyAI/banking77). Для русского языка есть небольшой классификатор на синтетических примерах. При наличии ключа `OPENROUTER_API_KEY` удалённая Qwen разбирает сообщения на русском и английском. Модель работает у провайдера; её веса не скачиваются на устройство пользователя.

**Состояние публикации:** код готов для отдельного облачного сервиса, но публичный адрес ещё не создан. Живой вызов OpenRouter/Qwen не проверен: ключ не предоставлен. Сервис финансового бота не менялся.

## Как проверить после публикации

1. Откройте публичный HTTPS-адрес сервиса. Учётная запись и установка программ для преподавателя не нужны.
2. Нажмите примеры под чатом или отправьте вопросы из таблицы ниже.
3. Панель справа объяснит маршрут и покажет источник ответа либо черновик для сотрудника.

| Вопрос | Ожидаемое поведение |
| --- | --- |
| `Сколько идёт доставка карты?` | Autopilot: учебная статья KB-001 |
| `Где мой платёж?` | Уточнение типа операции; реального статуса нет |
| `Какой статус у моей карты?` | Уточнение: доставка или состояние карты |
| `Какая у меня комиссия?` | Уточнение операции и тарифа; цифры не выдумываются |
| `Я не узнаю это списание` | Copilot: контекст и черновик для сотрудника |
| `Демо: покажи тестовый статус карты` | Явно помеченная синтетическая запись |

## Облачная публикация

1. Разместить содержимое этой папки в **отдельном** Git-репозитории. Файл `render.yaml` должен находиться в корне репозитория.
2. В Render создать Blueprint из этого репозитория. Конфигурация создаёт один бесплатный Python web service и проверяет `/api/health`.
3. В настройках сервиса задать секрет `OPENROUTER_API_KEY`, полученный из личной учётной записи OpenRouter. Ключ не помещать в Git, архив или переписку. При отсутствии ключа останется ограниченный локальный классификатор, работающий **на облачном сервере Render**.
4. После успешного развёртывания открыть выданный Render HTTPS-адрес и проверить все строки таблицы. Затем добавить этот адрес в файл сдачи.

Render Free может останавливать сервис после периода бездействия; первый запрос после простоя открывается дольше. Бесплатный маршрут Qwen у OpenRouter имеет лимиты и может временно быть недоступен. В этом случае прототип использует ограниченный классификатор и безопасное уточнение. [Render Free](https://render.com/docs/free), [OpenRouter pricing](https://openrouter.ai/pricing/), [Qwen 3.8 27B Free](https://openrouter.ai/qwen/qwen3.8-27b%3Afree).

Для учебной публикации не нужен действующий VPS финансового бота. Приложение не подключено к банковским системам и не обрабатывает реальные персональные данные. В демонстрации используйте вымышленные вопросы.

## Как формируется ответ

1. Правила для очевидной кражи карты и спорных списаний направляют вопрос в Copilot. Это экранная демонстрация передачи: настоящей очереди сотрудников нет.
2. Если задан ключ, Qwen получает вопрос, короткую историю и названия 77 тем Banking77. Она возвращает структурированную тему, тип случая, при необходимости уточнение с кнопками или черновик для сотрудника. Без ключа используются сохранённые модели классификации в облачном сервисе.
3. Для общего вопроса с подходящей статьёй приложение выдаёт текст из `knowledge_base.json` и ID статьи. Qwen не служит источником тарифов, сроков или личных статусов.
4. Для личного случая без доступа к банковским данным приложение уточняет запрос. Команда `Демо: покажи тестовый статус карты` отдельно показывает синтетический статус с маркировкой.
5. В Copilot видны история сообщений, отсутствие CRM/подтверждённого источника и редактируемый черновик. Черновик не отправляется клиенту автоматически.

## Данные, измерения и ограничения

- Banking77: 10 003 обращения в train, 3 080 в test, 77 тем, английский язык; лицензия CC BY 4.0. Источник: [PolyAI](https://huggingface.co/datasets/PolyAI/banking77).
- `knowledge_base.json` содержит **вымышленные** условия Демо-банка, составленные для этого прототипа. Banking77 содержит примеры вопросов и темы, но не банковские ответы.
- `evaluation_report.json`: английский классификатор на официальном test split, accuracy 0,905, macro F1 0,905. Из 172 автоматических ответов 165 выбрали верную тему; 0 из 480 рискованных вопросов получили автоответ.
- `ru_evaluation_report.json`: русский классификатор на 30 авторских синтетических тестовых фразах, accuracy 0,800, macro F1 0,796. Это маленькая учебная проверка, не независимая оценка качества на обращениях клиентов.
- Метрики локальных классификаторов **не измеряют** Qwen. Живой вызов OpenRouter и качество её маршрутизации ещё не проверены.
- Нет доступа к картам, платежам, CRM и реальным операторам. История диалога хранится только в браузере до обновления страницы.
- Публичный API ограничен 30 вопросами в час на адрес подключения. Это учебный лимит, не полноценная защита от злоупотреблений.

Цитирование датасета: Casanueva et al. (2020), *Efficient Intent Detection with Dual Sentence Encoders*, [arXiv:2003.04807](https://arxiv.org/abs/2003.04807).
